Velocity includes automatic dark mode with system preference detection and manual toggle.

## How It Works

1. Before the page renders, a small script checks `localStorage` for a theme the visitor chose with the toggle
2. If there isn't one, it uses `defaultTheme` from `site.config.ts`. With `'system'`, the default, it follows `prefers-color-scheme`
3. It adds or removes the `.dark` class on `<html>`
4. All semantic tokens switch values automatically

## Default Theme

Set `defaultTheme` in `src/config/site.config.ts` to choose what visitors see before they use the toggle:

```typescript
const siteConfig: SiteConfig = {
  // ...
  defaultTheme: 'dark', // 'system' | 'light' | 'dark'
};
```

| Value | Visitors who haven't used the toggle see |
|-------|-------------------------------------------|
| `'system'` | Their operating system's setting. This is the default |
| `'light'` | Light mode |
| `'dark'` | Dark mode |

A theme the visitor picks with the toggle always wins. You don't need to edit `src/layouts/theme-script.js`, which upgrades replace.

<Aside type="note">
  `defaultTheme` was added in Velocity 2.4.1. If your `SiteConfig` interface predates it, add `defaultTheme?: 'system' | 'light' | 'dark';` to it.
</Aside>

## Theme Toggle Component

```astro
---
import ThemeToggle from '@/components/layout/ThemeToggle.astro';
---

<ThemeToggle />
```

The toggle:
- Switches between light and dark
- Saves the choice in `localStorage`, so it overrides `defaultTheme` on later visits
- Updates immediately without a flash

## Token Switching

Semantic tokens swap values automatically:

```css
/* Light mode (default) */
:root {
  --background: var(--gray-0);      /* White */
  --foreground: var(--gray-900);    /* Near black */
}

/* Dark mode */
.dark {
  --background: var(--gray-950);    /* Near black */
  --foreground: var(--gray-50);     /* Near white */
}
```

## Preventing Flash

`BaseLayout` runs `src/layouts/theme-script.js` in `<head>`, before the page renders, so visitors never see the wrong theme first. It's rendered with `<InlineScript />`, which adds the script's hash to the page's CSP. `BaseLayout` passes `defaultTheme` to it as a `data-default-theme` attribute on `<html>`.

## Manual Control

### JavaScript API

```javascript
// Check current theme
const isDark = document.documentElement.classList.contains('dark');

// Set dark mode
document.documentElement.classList.add('dark');
localStorage.setItem('theme', 'dark');

// Set light mode
document.documentElement.classList.remove('dark');
localStorage.setItem('theme', 'light');

// Follow system
localStorage.removeItem('theme');
// Then check prefers-color-scheme
```

### CSS Targeting

```css
/* Target dark mode specifically */
.dark .my-component {
  /* Dark mode styles */
}

/* Or use Tailwind's dark: modifier */
<div class="bg-white dark:bg-gray-900">
```

## Reading the Theme in a Script

Pages are prerendered, so the server doesn't know the visitor's theme. Check the class on `<html>` in a client script:

```astro
<script>
  const isDark = document.documentElement.classList.contains('dark');
</script>
```

## Inverted Sections

For dark sections on light pages, use inverted tokens:

```astro
<section class="bg-surface-invert">
  <h2 class="text-on-invert">Title</h2>
  <p class="text-on-invert-muted">Description</p>
</section>
```

To flip every token inside a section, including the ones components use, wrap it in `.invert-section`:

```astro
<section class="invert-section bg-background">
  <h2 class="text-foreground">Title</h2>
  <Button>CTA</Button>
</section>
```

This works in both light and dark mode, maintaining proper contrast.

## Opting Out of Dark Mode

To disable dark mode entirely, remove the `.dark { ... }` block from your active theme file in `src/styles/themes/`. Without the `.dark` rule, the semantic tokens remain fixed at their light-mode values regardless of the toggle state.
