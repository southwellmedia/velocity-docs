The Input component provides text inputs with built-in label, hint, and error handling.

## Basic Usage

```astro
---
import { Input } from '@/components/ui';
---

<Input name="email" type="email" placeholder="you@example.com" />
```

## With Label and Hint

```astro
<Input
  label="Email"
  name="email"
  type="email"
  hint="We'll never share your email"
/>
```

## Error State

```astro
<Input
  label="Password"
  name="password"
  type="password"
  error="Must be at least 8 characters"
/>
```

## Errors After Interaction

Since 2.7, Input, Textarea and Select check themselves with the browser's own constraints (`required`, `type="email"`, `minlength`, `maxlength`, `min`, `max`). Nothing shows on page load or while someone is typing. Once a visitor leaves a field that isn't valid (the `:user-invalid` state), the field turns red and a message appears under it:

- The message is in the site's language, from `form.validation.*` in `src/i18n/ui.ts` (en, es, fr), and says how to fix the problem: "Use at least 10 characters (you have 9)." Override the keys in `src/i18n/translations/<locale>.ts`.
- It's linked to the field with `aria-describedby`, and the field gets `aria-invalid`, so screen readers read it with the field. Your own `aria-describedby` ids, for example external help text, are kept.
- It clears as soon as the value is valid.
- A message set with `setCustomValidity()`, and rarer states such as `pattern`, use the browser's own wording.

```astro
<Input label="Name" name="name" required minlength={2} maxlength={100} autocomplete="name" />
```

An `error` passed from the server still renders as before and takes precedence.

## With Icons

```astro
<!-- Leading icon -->
<Input
  label="Search"
  name="search"
  leadingIcon="search"
  placeholder="Search..."
/>

<!-- Trailing icon -->
<Input
  label="Amount"
  name="amount"
  trailingIcon="dollar-sign"
/>

<!-- Both icons -->
<Input
  label="Website"
  name="website"
  leadingIcon="globe"
  trailingIcon="external-link"
/>
```

```astro

```

## Inverted Variant

For inputs on dark backgrounds:

```astro
<section class="bg-surface-invert p-8">
  <Input
    variant="invert"
    label="Email"
    name="email"
    placeholder="you@example.com"
  />
</section>
```

## Props

| Prop | Type | Default | Description |
|------|------|---------|-------------|
| `label` | `string` | — | Label text |
| `error` | `string` | — | Error message |
| `hint` | `string` | — | Helper text |
| `size` | `'sm' \| 'md' \| 'lg'` | `'md'` | Input size |
| `variant` | `'default' \| 'invert'` | `'default'` | Color variant |
| `leadingIcon` | `string` | — | Icon at start |
| `trailingIcon` | `string` | — | Icon at end |
| `name` | `string` | — | Input name |
| `type` | `string` | `'text'` | Input type |
| `placeholder` | `string` | — | Placeholder text |
| `required` | `boolean` | `false` | Required field |
| `disabled` | `boolean` | `false` | Disabled state |

## Accessibility

- Label is properly associated with input
- Error messages are linked with `aria-describedby` and the field gets `aria-invalid`, both for server errors and for errors after interaction
- Required fields are marked
- Focus states are visible
