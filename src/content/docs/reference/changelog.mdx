## v2.6.2 (2026-11-09)

### More sections

Eight more page sections join Faq, Steps and the rest in `src/components/blocks/`: **FeatureGrid**, **FeatureSplit**, **Pricing**, **LogoCloud**, **StatsBand**, **ContactSection**, **Timeline** and **Team**. That makes 15. See [Sections](/components/sections/).

### New components

- **Sheet:** a side panel or bottom drawer on the native `<dialog>`.
- **Popover:** a small panel anchored to its button, using the native `popover` attribute.
- **Carousel:** scroll-snap slides with previous and next buttons.
- **ToggleGroup:** a segmented control built from radio inputs.
- **Kbd:** keys and shortcuts.
- **Spinner:** a loading spinner with a screen-reader label.
- **VideoEmbed:** a YouTube or Vimeo player that loads nothing from the provider until someone presses play.
- **AnnouncementBar:** a dismissible strip above the header.

See [Other UI components](/components/ui/other-components/). Velocity now has 70 components: 41 UI, 10 patterns, 15 sections, Breadcrumbs, 2 layout and 1 hero.

### Fixes

- **Breadcrumbs:** the JSON-LD for the current page now uses its own URL.

### Upgrading

Nothing breaks. The new files arrive with the upgrade.

## v2.5.1 (2026-11-08)

### Set up your site with your agent

- **`velocity-start-site` skill.** Ask your agent to "set up this site for my business". It asks what it can't work out, writes a brief, shows you the sitemap, builds your pages with Velocity's components and the other skills, and writes copy in every enabled language. See [Set up your site](/getting-started/ai-agents/#set-up-your-site).
- **The site brief.** `.agents/site.md` records the business, audience, voice, brand, sitemap, facts and decisions, so later sessions build on earlier ones. Upgrades leave it alone.
- **No invented facts.** Anything the agent doesn't know becomes a `[[placeholder: …]]` and is listed in the handoff.
- **`create-velocity-astro` 2.3** asks what you're starting (your own site, the demo or a blank project), then your site name and a one-line description, and seeds the brief with them. See [create-velocity-astro](/cli/).

### New agent checks

`check:agent` adds three warnings:

- `content/placeholder`: a placeholder or an empty `MediaSlot` image still on a page.
- `config/default-identity`: the scaffold's name, author or email in `site.config.ts`, or a build using `example.com` because `SITE_URL` isn't set.
- `a11y/multiple-h1`: a page with more than one `<h1>`.

### Fixes

- **Dark mode:** subtle and muted text in the default and Midnight themes, and status colours, now meet WCAG AA.
- **Starter blog post:** no longer renders two `<h1>`s.
- **404 page:** the large digits scale with the viewport.

### Upgrading

Nothing breaks. If you're on 2.5.0, the upgrade removes files Velocity no longer ships (backed up to `.velocity-backup/`); delete the `design` script from `package.json` if you have one. 2.5.1 replaces 2.5.0.

> **Upgrade guide:** [v2.4 to v2.5.1](/upgrade-guides/v2-4-to-v2-5/)

## v2.4.1 (2026-11-07)

### Agent checks that cover everything you build

- **Hardcoded text, everywhere you write code.** `check:agent` now scans every `.astro` and `.tsx` file under `src/`: pages written straight into `src/pages`, components in new folders, React islands, and new files inside Velocity's folders. Velocity's own untouched files are skipped.
- **Pages missing in other languages.** On a multilingual site, a page built outside the localized routes is now reported. Before, it existed in English only and the language switcher sent other visitors to their home page. Blog posts are exempt. Add a `velocity-single-language` comment to a page in `src/pages/` to opt out deliberately.
- **No more false broken links.** Links to server-rendered routes (`prerender = false`, including `[id]` and `[...rest]`), API endpoints, `redirects` from `astro.config` (both forms) and sites with a `base` path no longer fail `validate`.
- **Fewer false warnings.** Honeypot fields (`aria-hidden="true"`), lone HTML entities in JSX and deliberately empty translations are no longer flagged.
- `npm run check:agent -- --json` no longer truncates large output when piped.

### New

- **Customize the 404 page safely.** `src/pages/404.astro` now renders `src/views/NotFoundView.astro`, which is yours, so upgrades no longer overwrite a custom 404. See [Customizing the 404 Page](/customization/adding-routes/#customizing-the-404-page).
- **`defaultTheme` in `site.config.ts`.** Set `'light'` or `'dark'` to fix the theme for visitors who haven't used the toggle. `'system'`, the default, follows their operating system. See [Dark Mode](/design-system/dark-mode/#default-theme).

### Fixes

- **Midnight theme:** muted text in dark mode now meets WCAG AA (5:1).
- **Demo:** the component showcase shows the real component count.

### Upgrading

- **Custom 404?** The upgrade replaces `src/pages/404.astro` and saves your version in `.velocity-backup/`. Move your markup into `src/views/NotFoundView.astro`.
- **Edited the theme script?** Use `defaultTheme` in `src/config/site.config.ts` instead of editing `src/layouts/theme-script.js`. If your `SiteConfig` interface predates it, add `defaultTheme?: 'system' | 'light' | 'dark'`.
- **Stray test file.** If your project has `tests/unit/check-agent.test.ts`, delete it unless you've made it your own. 2.4.0 copied Velocity's own test there, and upgrades don't update `tests/`.
- **Expect new warnings.** The wider scan may report hardcoded text in pages or components it didn't check before. Move the text into `src/i18n/translations/<locale>.ts`, or add a `velocity-allow-hardcoded` comment to a file that is deliberately single-language.

> **Upgrade guide:** [v2.x to v2.4.1](/upgrade-guides/v2-to-v2-4/)

## v2.4.0 (2026-11-07)

### Built for agents

- **`npm run check:agent`** runs at the end of `validate` and in CI, and scans your source and build. Every finding names the file, the rule in `.agents/velocity.md` and the fix. See [The agent-ready check](/getting-started/ai-agents/#the-agent-ready-check).
  - **Errors:** translation keys with no English string or that render raw, inline scripts and handlers your CSP blocks, `javascript:` links, and broken internal links and anchors.
  - **Warnings:** forms still discarding submissions, edits to files Velocity replaces on upgrade, hardcoded user-facing text, and keys a language falls back to English for.
  - `--json` gives machine-readable output, and `--strict` makes warnings fail too.
- **Component reference:** `.agents/components.md` describes all 46 components, so agents use them instead of reinventing them. For each it gives what it's for, its props, variants, an example, and what to use instead.
- **Four new skills:** `velocity-rebrand`, `velocity-connect-forms`, `velocity-add-locale` and `velocity-add-content`.
- **Agent benchmark:** the same six tasks in Velocity, in Velocity without its agent files, and in plain Astro, scored independently. The harness is in `benchmark/` in the Velocity repository. Results will be published once runs are done.

### Fixes

- `PasswordInput`'s show/hide button label is translated.

### Upgrading

- **`validate`:** the upgrade adds `check:agent` to the end of your `validate` script. If you customized `validate`, append `&& node scripts/check-agent.mjs` yourself.
- **Baseline:** `create-velocity-astro` 2.1 records `.velocity/baseline.json` so the check can spot edits to Velocity-owned files. Commit it. With an older CLI, run `npm run check:agent -- --write-baseline` once.
- **Forms:** `check:agent` warns while a form has no delivery configured. Set `CONTACT_FORM_ENDPOINT` / `NEWSLETTER_ENDPOINT`, or ask your agent to use the `velocity-connect-forms` skill.

## v2.3.0 (2026-11-07)

### Forms that deliver

- The contact and newsletter Actions forward each submission as JSON to `CONTACT_FORM_ENDPOINT` / `NEWSLETTER_ENDPOINT` when set. `NEWSLETTER_API_KEY`, when set, is sent as a Bearer token. See [Forms & Actions](/api/#delivering-submissions).
- A failing endpoint now shows the form's error instead of reporting success. Redirects are refused, and logs show only the HTTP status, never the endpoint URL.
- With no delivery configured, the server logs a warning once per form that submissions are being discarded.
- New `src/lib/form-delivery.ts`, with unit tests.

### New projects get their own identity

- New projects start with a neutral `site.config.ts`, without Velocity's author, social links or demo phone and address, and a starter README that credits Velocity.
- The minimal starter's footer has a translated "Built with Velocity" link.
- The contact page shows the map only when an address is set.

### Cleanup

- The unused `ogImage` setting is removed from `site.config.ts`.

## v2.2.1 (2026-11-05)

### Share images for every page

- **Every page gets an image.** Images were only generated for routes and blog posts, so pages built from a collection pointed at a file that didn't exist. A build step now checks every finished page and draws what's missing.
- **Cards follow your brand.** They use your logo and `branding.colors.themeColor`, not a hardcoded orange. The "PAGE" badge is gone, and near-black theme colors get a white accent so they stay visible.
- **Missing custom images fail the build.** The error names the page and the file.

## v2.2.0 (2026-11-04)

### Your site, your design system

- **Your header and footer, in one file.** Every layout now renders `SiteHeader` and `SiteFooter` from `src/components/site/`. Change them once and every page follows. Upgrades never touch these files.
- **Themes can change anything.** Themes load last, so they can override any token. `--brand-hue` recolors the default brand scale from one value.
- **Buttons** follow `--primary`, and `--theme-radius-button` and `--theme-button-weight` style every button.
- **Logo** renders inline, so it can use `currentColor` and `--logo-accent`.
- **Header height:** `--header-offset` keeps content clear of a taller fixed header. Set it to `0` for a sticky one.
- **New patterns:** `Section`, `PageHeader` and `MediaSlot`. Drop a file in `src/assets/photos/` and `MediaSlot` shows it. Until then, a placeholder holds the space.
- **Button icons:** `leadingIcon` and `trailingIcon` props.

### Fewer silent failures

- A missing translation now fails `npm test` instead of showing raw text such as `services.title` on the page.
- E2E tests read your font and nav, so changing them no longer breaks the suite.
- Every route is checked in every enabled language.
- Skills read your project notes first, cover footer-only links, and use the new patterns in their examples.

### Fixes

- Local images no longer break the build on Windows. Velocity now uses one version of `sharp`.

### Upgrading

- **Blog index:** `src/views/BlogIndexView.astro` is yours, so upgrades leave it alone. Switch it to `SiteHeader` and `SiteFooter` by hand.
- **Edited layouts:** files in `src/layouts/` are replaced as usual and backed up to `.velocity-backup/`. Move header and footer changes into `src/components/site/`.
- **Buttons:** `primary` now uses `--primary`. Check your buttons if you customized `--primary`.

## v2.0.0 (2026-11-04)

### Velocity 2.0 on Astro 7

Velocity moves to **Astro 7.4**, and the CLI moves to **2.0**. This release has breaking changes and manual steps.

> **Upgrade guide:** [v1 to v2.0.0](/upgrade-guides/v1-to-v2/)

### Breaking Changes

- **Node.js 22.23.4 or later** is required. Node 24 LTS is recommended.
- **`/api/contact` and `/api/newsletter`** are replaced by Astro Actions.
- **`<ClientRouter />`** is removed in favor of native view transitions and prefetch.
- **`src/config/routes.ts` is gone.** Routes live in `src/config/nav.config.ts`, which is now protected from upgrades.
- **`create-velocity-astro` 2.0 or later** is required.

### Dependency Changes

- **Astro** upgraded to **7.4.5**, with **@astrojs/mdx 8** and **@astrojs/react 7**
- **tailwind-merge** upgraded to **3**, which understands Tailwind v4 syntax
- **ESLint** upgraded to **10**
- **satori** upgraded to **0.63**, **lucide-react** to **1**, **schema-dts** to **2**
- **Adapters added:** `@astrojs/node`, `@astrojs/vercel` and `@astrojs/netlify`
- **Removed:** `zod`, `astro-seo` and `@pagefind/default-ui`

### Features

- **Astro Actions** power the contact and newsletter forms, with typed input and translated validation messages
- **Automatic adapters** for Vercel, Netlify, Cloudflare (opt-in) and Node, with CDN route caching
- **Strict CSP** by default, with hashes for inline scripts
- **Site search** with Pagefind at `/search`
- **Fonts API** with self-hosted fonts and metric-matched fallbacks
- **Core i18n:** every component is locale-aware, with translated slugs, `hreflang`, a no-JavaScript language switcher, per-language search and localized OG images
- **Views:** page content moves to `src/views/`, and `src/pages/` holds thin wrappers
- **Tests:** Vitest unit tests and Playwright end-to-end and axe accessibility tests
- **`AGENTS.md`** for AI coding agents, and `pnpm dev:bg` for a background dev server
- **Faster:** production builds dropped from 13.9s to 6.3s, and baseline JavaScript from 5.7 KB to 1.2 KB gzipped

### CLI 2.0

- **No bundled templates.** The CLI downloads Velocity and applies the `scaffold` section of its manifest, so the two can't drift
- **`--ref` and `--template`** choose the Velocity version, and the latest release is now the default
- **`--no-install`** skips dependency installation
- **`--pages`** rewritten for views, wrappers, nav and translations, and it accepts a list of names
- **Upgrades replay your variants,** so minimal and i18n projects are compared with the right files
- **All eight project shapes** are built in CI

### Bug Fixes

- **`--i18n` projects** failed to build in CLI 1.x
- **Forms** never ran on static builds, and the blog's subscribe form had no handler
- **Blog OG images** pointed at files that didn't exist
- **Partial component installs** deleted files still in use, because of gaps in the component registry
- **`--demo` with a partial selection** could never build
- **`cn()`** dropped classes when mixing Tailwind v4 syntax
- **`PageLayout`** rendered a second `<main>`
- **`@tailwindcss/typography`** was missing, so blog posts rendered unstyled
- **Dates** showed a day early in US time zones, and reading time was estimated from the description
- **Lint** failed on `main` because pnpm hid `@typescript-eslint/parser`
- **Accessibility:** entrance animations ignored `prefers-reduced-motion`, and the "Featured" badge and code comments failed WCAG AA contrast

## v0.4.5-beta (2026-02-15)

### Features

- **Cookie Consent Manager** — Full consent banner with Accept All / Decline All / Customize, per-category settings panel via Dialog, Google Consent Mode v2 integration, localStorage persistence with versioned re-consent
- **Two consent modes** — `consent_mode_v2` (cookieless pings with denied defaults) and `strict` (full script blocking until consent)

### Security

- **Removed Astro CSP** — Auto-hashing of `<style>` blocks makes `'unsafe-inline'` ineffective per the CSP spec. Will revisit when the Astro CSP API is stable.
- **Simplified security headers** — 4 zero-maintenance headers via `vercel.json`: `X-Content-Type-Options`, `X-Frame-Options`, `Referrer-Policy`, `Permissions-Policy`
- **Dropped `X-XSS-Protection`** — Deprecated header that can introduce vulnerabilities in older browsers
- **Kept `checkOrigin: true`** — CSRF protection via Astro's origin checking

### Bug Fixes

- **Fixed mobile menu backdrop blur** — `.mobile-menu-blur` was in a scoped `<style>` block but applied to elements outside the Header component; changed to `<style is:global>`
- Fixed Analytics race conditions and duplicate event listeners
- Fixed dynamic consent mapping bugs in GCM integration
