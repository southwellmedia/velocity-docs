Solutions for common CLI issues.

## Template Issues

### Download fails

The message `Could not download southwellmedia/velocity#<ref>` means the download failed or the ref doesn't exist.

1. Check your internet connection and that GitHub is reachable
2. If you passed `--ref`, check that the tag or branch exists

### "Could not determine the latest Velocity release"

The CLI couldn't reach the GitHub API within a few seconds, or hit the rate limit, so it used the `main` branch instead. To get a release, either pin one or set a token:

```bash
pnpm create velocity-astro my-site --ref v2.0.0

# Or raise the rate limit
GITHUB_TOKEN=your-token pnpm create velocity-astro my-site
```

### "has no scaffold section"

The Velocity version you chose predates version 2. Pick a 2.x release with `--ref`. To create a project on an older Velocity, use `create-velocity-astro@1`.

### "requires create-velocity-astro >= x"

The Velocity release needs a newer CLI. Use the latest one:

```bash
npm create velocity-astro@latest
```

### "Use either --ref or --template, not both"

Pass only one of them.

## Flags Are Ignored with npm

npm treats flags as its own unless they come after `--`:

```bash
npm create velocity-astro@latest my-site -- --demo --i18n
```

## Directory Issues

### Directory already exists

In the wizard, the CLI asks before writing into a non-empty folder. With `--yes`, it stops with an error, so choose a different name or empty the folder first.

## Dependency Installation

### Installation fails

The project is still created. Install dependencies yourself:

```bash
cd my-site
pnpm install  # or npm install / yarn / bun install
```

`--yes` installs with the package manager you ran the CLI with. To use a different one, add `--no-install`, delete `pnpm-lock.yaml` if you're not using pnpm, and install it yourself.

### Node version errors

The CLI itself needs Node.js 20.19 or later. Generated projects need 22.23.4 or later, because Astro 7.4 requires it. Node 24 LTS is recommended:

```bash
node --version

# Update with nvm
nvm install 24
nvm use 24
```

The CLI only warns about this when scaffolding, but `upgrade` stops.

## Component Issues

### Missing components

Check `features.components` in `.velocity.json` to see what you selected. To add a component later, copy its files from [Velocity](https://github.com/southwellmedia/velocity) using the paths in `component-registry.json`, along with its dependencies.

### Import errors from `@/components/ui`

Partial installs remove the barrel files. Import from the component's folder:

```astro
---
import Button from '@/components/ui/form/Button/Button.astro';
---
```

### Generated types are out of date

```bash
pnpm astro sync
```

## `--pages` Issues

### A page was skipped

The CLI skips a page if its name is reserved (`index`, `blog`, `404`, `rss`, `search`, `lang`), and warns if the route, view or page file already exists.

### "--pages requires Velocity 2"

The project has no `src/views/` folder or no `routes` export in `src/config/nav.config.ts`. This only happens when scaffolding from a modified template.

## Upgrade Issues

### "This doesn't appear to be a Velocity project"

Run `upgrade` from the project root. The command needs a `.velocity.json` file, which projects get from the CLI. Projects cloned by hand don't have one.

### Files were overwritten

Check `.velocity-backup/<old-version>/` for your versions. See [Conflicts](/cli/upgrade/#conflicts).

## i18n Issues

### A language doesn't show up

Check that it's listed in `src/i18n/locales.mjs`. See the [i18n guide](/configuration/i18n/).

### Text appears in English

A key missing from a language falls back to English. Add it to `src/i18n/translations/<locale>.ts`.

## Git Issues

### Git not initialized

If git isn't available, the CLI skips this step. Install [git](https://git-scm.com/downloads), then:

```bash
cd my-site
git init
git add .
git commit -m "Initial commit"
```

## Getting Help

1. Check the [CLI issues](https://github.com/southwellmedia/create-velocity-astro/issues) and [Velocity issues](https://github.com/southwellmedia/velocity/issues)
2. Search for your error message
3. Open a new issue with your Node.js version, package manager, full error message and steps to reproduce

<Aside type="note">
  Include the output of `npm create velocity-astro@latest -- --version` in bug reports.
</Aside>
