Every Velocity 2 project can be multilingual: routing, the language switcher, `hreflang` tags, search and social images are all in core. The `--i18n` flag just turns on the languages that ship with translations.

```bash
pnpm create velocity-astro my-site --i18n
```

Or answer **Yes** in the wizard:

```
◇  Add internationalization (i18n)?
│  ○ No
│  ● Yes
```

## What the Flag Changes

| File | Change |
|------|--------|
| `src/i18n/locales.mjs` | Lists `en`, `es` and `fr` |
| `src/i18n/translations/es.ts` | Spanish site copy |
| `src/i18n/translations/fr.ts` | French site copy |

That's the whole difference, so you aren't locked in. You can enable languages later in a project created without the flag. The [i18n guide](/configuration/i18n/) shows how, along with adding other languages and translating pages and posts.

## URLs

English is the default language and has no prefix. Other languages use a prefix and can have translated slugs:

```
/                    English home
/about               English about page
/es/                 Spanish home
/es/sobre-nosotros   Spanish about page
/fr/a-propos         French about page
```

<Aside type="note">
  Projects created with `--i18n` in CLI 1.x need a one-off migration. See the [v1 to v2 upgrade guide](/upgrade-guides/v1-to-v2/).
</Aside>
