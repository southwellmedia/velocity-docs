Cloudflare is opt-in, because its adapter pulls in the `workerd` runtime and most projects don't need to download it.

## Setup

<Steps>
1. **Install the adapter**

   ```bash
   pnpm add @astrojs/cloudflare
   ```

2. **Finish the Worker setup**

   Follow [Astro's Cloudflare guide](https://docs.astro.build/en/guides/integrations-guide/cloudflare/) for the Worker entrypoint. Velocity's `wrangler.toml` already has an `[assets]` block that serves the prerendered site.

3. **Build**

   The adapter is detected in CI from `CF_PAGES` or `WORKERS_CI`. To force it elsewhere:

   ```bash
   DEPLOY_TARGET=cloudflare pnpm build
   ```

4. **Deploy**

   ```bash
   pnpm add -g wrangler
   wrangler login
   wrangler deploy
   ```
</Steps>

<Aside type="caution">
  If the adapter isn't installed, the build stops with a message telling you to run `pnpm add @astrojs/cloudflare`.
</Aside>

## Why an Adapter Is Needed

Velocity's forms use Astro Actions, which need a server runtime. Pages stay prerendered, and only actions and routes you mark `prerender = false` run in the Worker.

Route caching uses the Cloudflare provider. See [Route Caching](/deployment/#route-caching).

## Environment Variables

Set these in your Cloudflare project settings:

```bash
SITE_URL=https://your-project.example.com
PUBLIC_GA_MEASUREMENT_ID=G-XXXXXXXXXX
```

Use Node.js 22.23.4 or later for the build.

## Security Headers

`vercel.json` and `netlify.toml` send Velocity's security headers on those hosts. On Cloudflare, add them with a `public/_headers` file or a Transform Rule.

## Troubleshooting

### Forms Don't Submit

Check that the build used the Cloudflare adapter. Without it, the build falls back to the Node adapter, which Cloudflare can't run. Set `DEPLOY_TARGET=cloudflare` if your build environment doesn't set `CF_PAGES` or `WORKERS_CI`.

### Build Failures

Check that your build uses a supported Node version and that `@astrojs/cloudflare` is in `package.json`.
