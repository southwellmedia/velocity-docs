The `contact` action handles submissions from the `ContactForm` component.

## Fields

| Field | Type | Required | Validation |
|-------|------|----------|------------|
| `name` | string | Yes | 2–100 characters |
| `email` | string | Yes | Valid email format |
| `subject` | string | No | Up to 200 characters |
| `message` | string | Yes | 10–5000 characters |
| `honeypot` | string | No | Hidden spam trap |

## Schema

```typescript
// src/lib/forms.ts
export const contactSchema = z.object({
  name: z.string().trim().min(2, 'form.errors.nameTooShort').max(100, 'form.errors.nameTooLong'),
  email: z.email('form.errors.invalidEmail'),
  subject: z.string().trim().max(200, 'form.errors.subjectTooLong').optional(),
  message: z
    .string()
    .trim()
    .min(10, 'form.errors.messageTooShort')
    .max(5000, 'form.errors.messageTooLong'),
  honeypot: z.string().optional(),
});
```

## Handler

The handler in `src/actions/index.ts` forwards the message to `CONTACT_FORM_ENDPOINT` when it's set. Otherwise it discards the message and logs a warning:

```typescript
contact: defineAction({
  accept: 'form',
  input: contactSchema,
  handler: async ({ honeypot, ...data }) => {
    // Bots fill hidden fields. Report success so they don't retry, but drop it.
    if (honeypot) return { success: true };

    if (CONTACT_FORM_ENDPOINT) {
      await deliver('contact', () => postJson(CONTACT_FORM_ENDPOINT!, data));
      return { success: true };
    }

    // @velocity-stub contact (no delivery configured: discarded, see npm run check:agent)
    warnUndelivered('contact', 'CONTACT_FORM_ENDPOINT');
    // ...
    return { success: true };
  },
}),
```

`deliver()` turns any delivery failure into an `ActionError`, so the form shows its error message. See [Delivering Submissions](/api/#delivering-submissions).

## Forwarding to an Endpoint

Set `CONTACT_FORM_ENDPOINT` in `.env` and on your host. Each submission is POSTed as JSON:

```json
{ "name": "Ada", "email": "ada@example.com", "subject": "Hello", "message": "..." }
```

Any non-2xx response, or a redirect, shows the form's error.

## Sending Email

To send email directly, replace the forwarding and the `@velocity-stub` block with your provider's code. Delete the `@velocity-stub` line so `check:agent` stops warning.

### Resend

```typescript
import { Resend } from 'resend';
import { ActionError } from 'astro:actions';
import { RESEND_API_KEY } from 'astro:env/server';

const resend = new Resend(RESEND_API_KEY);

const { error } = await resend.emails.send({
  from: 'Website <hello@yoursite.com>',
  to: 'you@yoursite.com',
  replyTo: data.email,
  subject: data.subject ?? `Message from ${data.name}`,
  text: data.message,
});

if (error) {
  throw new ActionError({ code: 'INTERNAL_SERVER_ERROR', message: 'Could not send message' });
}
```

Add secrets to `env.schema` in `astro.config.mjs` so `astro:env/server` can read them. See [Environment Variables](/configuration/environment/).

## Using Your Own Endpoint

`ContactForm` calls the action by default. To post somewhere else, pass `action`:

```astro
<ContactForm action="/api/my-endpoint" />
```

The endpoint receives `FormData` and must return JSON: `{ "success": true }` or `{ "success": false, "errors": { "email": ["..."] } }`.

<Aside type="caution">
  The CSP sets `form-action 'self'`. Same-origin paths work without changes, and the form submits through JavaScript. If you need a plain cross-origin form post, add that origin to the directive in `astro.config.mjs`.
</Aside>
